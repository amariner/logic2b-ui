title: Instalación
description: Configura tu proyecto y empieza a usar los componentes de logic2b ui.
---

Esta guía usa `logic2b@next`, el canal beta de npm. `next` puede cambiar:
registra `npx logic2b@next --version` al comunicar un problema. El selector
`--registry-version` controla el registro, no la versión del paquete CLI.

## Requisitos

- React 18 o posterior (React 19 recomendado)
- Tailwind CSS v4

## Compatibilidad

La versión `1.0.0` aún no se ha publicado. En npm, `latest` sigue apuntando a
las versiones antiguas de CLI `0.4.0` y MCP `0.2.0`; usa `next` para los
paquetes beta actuales y el registro. Las versiones siguientes son con las
que se verificó esta documentación.

| Área | Beta actual | Notas |
| --- | --- | --- |
| Contenido del registro | `1.0.0-rc.16`, canal `next` | Manifiestos inmutables; SHA-256 verificado por CLI y MCP |
| Paquetes CLI y MCP local | `logic2b@next`, `@logic2b/mcp@next` (publicado `1.0.0-rc.2`; las novedades del MCP remoto siguen pendientes en npm) | Node.js 18+ con npm, pnpm, yarn o bun |
| Componentes | React 19.2, Tailwind CSS 4.3, TypeScript 6 (pins del registro) | La mayoría funciona también con React 18 |
| Starters generados | Next.js 16.3, Vite 8.2, Astro 7.2 | Pins exactos en cada `package.json` generado |
| MCP remoto (`/mcp`) | HTTP streamable, sin estado, herramientas de solo lectura | Devuelve planes y fuentes verificadas; no escribe archivos |
| Capacidades del host para aplicar un plan | Escritura de archivos; gestor de paquetes y runtime de build para instalar y verificar | Un host solo de chat puede inspeccionar y planificar |
| Extensión de VS Code | VSIX de vista previa `0.1.0` generado por CI | No publicada en el Marketplace |
| Desarrollo del repositorio | Node.js 22.12+, pnpm 11.10 | Ver CONTRIBUTING.md |

## 1. Instala las dependencias base

```bash
pnpm add clsx tailwind-merge class-variance-authority radix-ui lucide-react
```

## 2. Añade el helper cn()

Crea `src/lib/utils.ts`:

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

También puedes instalarlo desde el registro:

```bash
npx logic2b@next add utils
```

## 3. Añade los tokens del tema

Copia las variables CSS de la página de [Temas](/es/docs/theming) a tu hoja de
estilos global. Los componentes usan tokens como `bg-primary` y
`text-muted-foreground`; sin ellos el diseño no será correcto.

## 4. Añade componentes

```bash
npx logic2b@next add button
```

También puedes copiar el código desde cualquier página de componente.

Para instalar una superficie de marketing completa como una sola composición:

```bash
npx logic2b@next add landing-page-01
```

El registro resuelve de forma transitiva su navbar, hero animado, cuadrícula de
funcionalidades, CTA y footer. Cada pieza sigue siendo instalable y actualizable
por separado.

## Instalaciones versionadas y actualizaciones seguras

Inicializa el proyecto para fijar la versión exacta del registro:

```bash
npx logic2b@next init
npx logic2b@next add button card
npx logic2b@next status
```

`init` escribe `logic2b.version` en `components.json`. Cada instalación también
queda registrada en `.logic2b/manifest.json` con la versión resuelta, la
integridad SHA-256 de cada elemento y sus archivos. Así los mismos datos de
entrada se pueden reproducir aunque un canal avance más tarde.

Los presets de [/create](/create) también guardan la librería de iconos. Elige
Lucide, Tabler, Phosphor o Hugeicons; `init --preset <id>` conserva la selección
como `iconLibrary`, y `add`/`update` reescriben juntos imports, dependencias npm y
snapshots de mezcla.

Puedes seleccionar una versión exacta, un rango semver o un canal publicado:

```bash
npx logic2b@next add button --registry-version 1.0.0-rc.16
npx logic2b@next status --registry-version next
npx logic2b@next update --registry-version "^1.0.0"
```

`logic2b update` solo considera los elementos registrados en el manifiesto, a
menos que indiques nombres. Realiza una mezcla de tres vías contra el snapshot
capturado al instalar: actualiza archivos intactos, conserva cambios locales,
mezcla cambios compatibles y marca los solapamientos para revisión. Consulta
`/r/changelog/<name>.json` antes de ampliar un rango.

## Uso con un asistente de IA

Cada bloque de instalación incluye una pestaña **Agent** y el estudio de temas
incluye una vista **Prompt**. Un asistente conectado al MCP de logic2b puede
partir de un directorio vacío: pídele que use `scaffold_plan` con un framework
(`next`, `vite` o `astro`) y un starter (`marketing`, `dashboard` o `auth`). La
respuesta contiene todos los archivos, el tema, dependencias transitivas y la
integridad de la versión resuelta.

## Instrucciones del proyecto para agentes

El candidato del repositorio incorpora reglas gestionadas con `init`, `add` y
`update`, y un `DESIGN.md` separado como referencia de tokens. Esta novedad está
pendiente de la publicación conjunta en npm; comprueba la ayuda de la CLI antes
de usarla con `@next`. Desde un checkout del repositorio puedes generar los
archivos para una app existente:

```bash
pnpm --filter logic2b dev rules --cwd /path/to/project --format agents --format claude
```

Los formatos son `agents`, `design`, `claude`, `cursor` y `copilot`. Claude
incluye una importación `@AGENTS.md`; Cursor usa `.cursor/rules/logic2b.mdc`;
Copilot añade una sección gestionada en `.github/copilot-instructions.md`.
`DESIGN.md` acompaña a cualquier selección. Se conserva el texto situado fuera
de los marcadores versionados de logic2b; los marcadores incorrectos y las
precondiciones de archivo obsoletas detienen la actualización. Repetir el
comando con los mismos metadatos no cambia los archivos.

En una CLI que anuncie la opción, `--no-agent-rules` desactiva la generación
automática al inicializar, instalar o actualizar. El comando explícito `rules`
sigue disponible. La preview de VS Code del código fuente también ofrece
**logic2b: Generate Agent Rules…**, selección de formatos y la opción
`logic2b.agentRules.enabled` para desactivar la actualización automática. Las
escrituras usan la API del workspace.

Las reglas registran los elementos instalados y las responsabilidades de
verificación. Conservan controles nativos, wrappers, textos y tokens propios,
y usan herramientas MCP solo cuando están disponibles. Los manifiestos y
snapshots de `.logic2b` siguen siendo propiedad de la CLI. Consulta
[Para LLM y agentes](/es/docs/llms) para el plan MCP de solo lectura y la skill
procedimental opcional de Claude Code.

## Alias de rutas

El código del registro usa por defecto `@/lib/utils` y `@/components/ui/*`.
En una app nueva, configura el alias en TypeScript y en el bundler. En una app
existente, confirma los alias y destinos antes de adaptar esos imports;
conserva las carpetas UI personalizadas en vez de asumir `src/`.
